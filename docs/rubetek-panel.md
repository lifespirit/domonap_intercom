# Авторизация Rubetek Panel

Интеграция поддерживает два независимых профиля авторизации:

- **Номер телефона + SMS** — исходный режим интеграции. Его поведение сохранено для существующих записей.
- **Rubetek Panel** — профиль стационарной AOSP/Rubetek-панели. Он использует отдельную panel-сессию и не требует номера телефона Home Assistant.

## Получение 8-значного кода

Для новой Rubetek Panel нужен **8-значный код активации**.

Код не генерируется Home Assistant и не приходит по SMS. Его необходимо запросить через поддержку в официальном приложении Domonap. В обращении укажите, что нужен код активации стационарной/Rubetek-панели для вашего объекта. Поддержка выдаёт восьмизначный код.

> Код следует считать одноразовым provisioning-кодом. Интеграция использует его только для обмена на постоянную panel-сессию и не сохраняет сам код в Home Assistant.

## Добавление новой записи

1. Откройте **Настройки → Устройства и службы → Добавить интеграцию → Domonap**.
2. В поле профиля авторизации выберите **Rubetek Panel**.
3. Выберите **Новый 8-значный код активации**.
4. Введите код, полученный от поддержки Domonap.
5. После успешного обмена Home Assistant сохранит panel-сессию в записи интеграции.

Внутри интеграции код обменивается через panel endpoint Domonap на `completeToken`, после чего сохраняются access/refresh token, срок действия refresh token, идентификатор panel principal и параметры device identity.

## Импорт существующей panel-сессии

Для уже активированной панели предусмотрен второй вариант — **Существующая активированная сессия**. Он полезен, если код уже был использован и у вас есть ранее экспортированные данные panel-сессии.

Ожидаемый JSON имеет вид:

```json
{
  "instanceId": "0123456789abcdef",
  "deviceInfo": {
    "InstanceId": "0123456789abcdef"
  },
  "panel": {
    "userId": "REDACTED",
    "name": "Rubetek Panel"
  },
  "completeToken": {
    "accessToken": "REDACTED",
    "refreshToken": "REDACTED",
    "refreshExpirationDate": "2030-01-01T00:00:00Z"
  }
}
```

Токены являются учётными данными. Не публикуйте такой JSON в issue, логах, примерах конфигурации или репозитории.

Интеграция проверяет, что:

- `instanceId` состоит из 16 шестнадцатеричных символов;
- access token содержит роль `Panel`;
- refresh token ещё действителен.

## Чем Panel отличается от phone/SMS

Panel runtime изолирован от старого мобильного профиля:

- не регистрирует FCM/HMS `deviceToken`;
- использует прямое SignalR WebSocket-соединение `notificationHub`;
- для каждого входящего вызова получает временные SIP credentials;
- может опционально передавать вызов на внешний SIP/Asterisk;
- поддерживает несколько независимых Panel-записей одновременно.
